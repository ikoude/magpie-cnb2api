# magpie-cnb2api

在 magpie 里使用你自己 CNB 工作区中的 **cnb2api** 网关。

装好之后，magpie 会多出一个 **CNB2API** 供应商，所有 agent 都能直接用。
你只需要把网关地址和模型填一次，之后地址漂移、工作区被停、额度耗尽，
都发生在插件背后，配置不用再动。

> 文中的 `alice`、`acme`、`acme/my-gateway` 与数字均为示例。

---

## 1. 它解决什么

cnb2api 跑在 CNB 工作区里，有两个天然毛病：

| 毛病 | 表现 | 插件怎么做 |
|---|---|---|
| **地址会漂移** | 工作区每次重启，`<随机串>-9001.cnb.run` 就换一个 | 后台盯着，地址一变，下一个请求自动走新地址 |
| **工作区会停** | 平台会回收，停了就完全没响应 | 定时检查，停了就提交启动，并等到新地址出现 |

另外还做三件事：把每个组织的**真实额度**（AI credits、核时）显示到 magpie
的用量面板；**按组织拆分账号**；在额度用尽时**不白烧核时**。

---

## 2. 账号是什么：用户名 + 组织/仓库

这是本插件和别处最大的不同。

一个 CNB 账号可能同时属于几个组织，而**每个组织有自己的 AI credits**。
把一个人看成一个账号，就会用 A 组织的额度去解释 B 组织的余额，
面板上的数字永远对不上。所以：

```
alice | acme/my-gateway      ← 一个账号：alice 在 acme 下的网关
alice | @beta                ← 另一个账号：同一个 alice，但 beta 组织的额度
```

- 账号标识（`accountId`）和显示名都是这个字符串。
- **不用邮箱当身份**。CNB 令牌未必带邮箱；即使带，邮箱也会随改名变化，
  而且说明不了「这是哪个组织」。
- 同一个人在不同组织下是不同账号；两个人在同一组织下也是不同账号。
- 仓库只属于它所在的那个组织；其它组织用 `@组织` 表示，由插件自动发现仓库。

magpie 判断两个登录是不是同一个账号，读的是登录结果里的 `accountId`。
插件给出的标识始终是上面这种形式，所以多账号不会被合并，也不会互相覆盖。

**加多个账号就登录多次**：magpie 一次登录只产生一个账号，所以同一个人在
`acme`、`beta` 两个组织，要执行两次 `magpie plugin login cnb2api`，每次选一个组织。
两个组织常常共用同一个 PROXY_KEY，因此身份必须挂在 `accountId` 上，不能靠密钥区分。

> magpie 的 `save()` 对 API 类型登录只保存 `type/key/metadata`，顶层 `accountId`
> 会被丢掉，随后按密钥判重、把第二个账号替换掉。插件的登录结果带空的
> `refresh` 字段，走另一条会保留顶层 `accountId` / `uid` 的保存分支；
> `refresh` 是空串，账号不会被续期，也不会过期。

## 3. 安装与登录

```bash
magpie plugin add /path/to/magpie-cnb2api
magpie plugin login cnb2api
```

登录是联动下拉，不用背 org/repo 的写法：

```
① CNB 访问令牌（CNB → 头像 → 访问令牌）        ← 手填
② 选择组织（只列组织；选项名称直接显示「已用/额度 cr」，悬停不重复） ← 下拉
③ 选择仓库（显示运行中/已停止、是否识别到网关）    ← 下拉
④ PROXY_KEY（.cnb.yml 里设的那个）             ← 手填
```

组织列表只列你加入的组织（仓库前缀与组织列表合并），**不含你的用户名**——
用户名是「人」不是「组织」。如果没有任何组织、或只想用个人命名空间，
可以在组织那一步直接手填名字。

**仓库叫什么名字都行**。判定依据是启动日志里有没有 `PROXY_URI=`，
不是仓库名里有没有 `cnb2api`。名字带 cnb2api 但日志里没有地址的仓库
不会被当成候选。

**选错了可以重选**：仓库下拉最后一项是「↩ 重新选组织」，选中即回到
组织那一步；也可以留空让插件稍后自动识别。确定要改账号时，重新执行
`magpie plugin login cnb2api` 即可。

**自动识别不到时也不是死路**：下拉会把该组织下所有有工作区的仓库都列出来，
没识别到网关的标 `⚠ 没识别到，可手动选`，用户可以直接选；也可以留空，
之后用 `magpie plugin options` 手工填 `repo`。

省事的处理：

- 只有一个组织 / 一个候选仓库时，给出**单选列表**，选中即可（留空选项也在，可交给插件自动识别）；
- 一个仓库都没查到时给「留空，稍后自动识别」选项，不卡住流程；
- 令牌填成 `sk-` 开头会当场点明「这是 PROXY_KEY，不是访问令牌」；
- 两栏填同一个值会当场拦下。

### 两类凭据，别填混

| 凭据 | 长什么样 | 干什么用 | 从哪拿 |
|---|---|---|---|
| **CNB 访问令牌** | 一串字母数字，**不是** `sk-` 开头 | 调 CNB OpenAPI：列工作区、读日志、拉起工作区 | CNB → 头像 → 访问令牌 |
| **PROXY_KEY** | 通常 `sk-` 开头 | 调你自己工作区里的 cnb2api 网关 | `.cnb.yml` 中 `env` 的 `PROXY_KEY` |

### token 权限

| Scope | 用途 | 缺少的后果 |
|---|---|---|
| `repo-cnb-trigger:r` | 读启动日志，从 `PROXY_URI=` 提取地址 | **不可用**：拿不到地址 |
| `account-engage:r` | 列出工作区 | **不可用**：找不到工作区 |
| `repo-cnb-trigger:rw` | 拉起已停止的工作区 | 地址还能跟随，但停了不会自动拉起 |
| `group-resource:r` | 显示组织额度；启动前查额度 | 面板不显示额度，启动前也不再拦截 |
| `account-engage:rw` | 停止工作区（省核时） | `idleStopMinutes` 与停止工具用不了 |

最小可用组合：`repo-cnb-trigger:rw` + `account-engage:r`。
插件启动时会自检一遍，缺哪一项、影响什么，都写进日志，不用对着 403 猜。

## 4. 地址跟随

取地址只有一条可靠来源：工作区流水线日志里的 `PROXY_URI=` 行。
CNB 的 `workspace/detail` 返回的 `webide` 是 cnb.cool 控制台地址，不是网关地址；
`cnb.run` 又是泛解析，DNS 探测和 HTTP 猜地址都会得到假阳性。

地址识别口径与 `dsh-cnb2api` 插件一致：

- 先剥掉 ANSI 颜色码（日志常带 `\x1b[...m`）；
- 认 `PROXY_URI=` / `PROXY_URI:` / `PROXY_URI =`，值可带引号；
- 取**最后**一条（热重启会再打印一次，前面那条已失效）；
- 只保留 `cnb.run` 主机，丢掉值里可能带的 `/v1` 路径，避免拼成 `.../v1/v1`；
- 兜底：日志里直接 echo 的裸 `cnb.run` 主机（没有 `PROXY_URI` 前缀也认）。

日志里的值形如：

```
PROXY_URI=https://tm5fw16v80-{{port}}.cnb.run
```

`{{port}}` 是模板，必须换成真实端口（默认 9001），否则是个非法主机名。
热重启会打印多条，取最后一条。

**关键细节**：地址一变就立刻采用，**不先验活**。新工作区刚起来时代理要几十秒才监听，
如果因为「暂时不通」就丢掉新地址，就会一直卡在已经失效的旧地址上。

插件用动态 `baseURL` 加请求时的强制改写，双保险：不管 magpie 存下的是哪个地址，
每个请求都会重写成当前地址。地址失效时并发请求共用同一次恢复动作，不会
各自把 CNB 接口打成筛子。

### 凭据变化

换 token 或 PROXY_KEY 时，该账号的地址、工作区编号、失败计数、错误状态
全部作废并立刻重新识别；不需要重启 magpie，也不会让新 token 用着旧地址。

## 5. 工作区生命周期

### 自动拉起

巡检（默认每 120 秒）发现工作区不在 running，就提交一次启动，用配置里的分支。
提交后 **60 秒内不重复提交**：工作区从启动到平台翻成 running 要几十秒，
每轮巡检都 POST 一次只会打成连发。

手动停过之后，巡检**不会**再自动拉起——那等于白停。等真的有请求进来再说。

### 额度闸门：不白烧核时

组织 AI credits 用尽时，cnb2api 对每个请求都回 `402 [EXCEEDING_LIMIT]`。
这时启动工作区只会白等 30–90 秒并消耗核时，所以启动前先查额度：

| 情况 | 行为 |
|---|---|
| 可用额度 ≤ 0 或低于保底线 | 不提交启动；补足后巡检自动再试 |
| 额度查不到（缺权限 / 接口失败） | **照常启动**：拦住一个能用的，比放过一个注定 402 的更糟 |
| 余额很少但 > 0 | 照常启动，面板按警戒线提示 |

判定口径与「可不可用」一致。查不到数字时不拦，也不谎报 0%。

### 空闲自动停止

```bash
magpie plugin options magpie-cnb2api '{"idleStopMinutes": 30}'
```

工作区 running 就按时间扣核时，不发请求也在扣。上面这个配置会在
超过 30 分钟没有请求时自动停掉。

- 计时从「拿到可用地址」或「最后一次请求」开始
- 停之前会探活一次，工作区已经挂掉就不重复停
- `0`（默认）= 不自动停
- 需要 `account-engage:rw` 权限

## 6. 用量面板

```
CNB2API · starting
  alice | acme/my-gateway   workspace       ok · 860l****-9001.cnb.run
                            AI credits · acme   ▓▓▓░░░  6.8 / 1166 cr  赠送 +666 · 预扣 2 · 可用 1188
```

| 显示项 | 含义 |
|---|---|
| `6.8 / 1166 cr` | 已用 + 预扣 / 总额（总额已含加成） |
| `预扣 2` | 已占用但尚未结算的部分 |
| `可用` | 总额 − 已用 − 预扣 |
| `AI credits · acme 6.8/1166 cr` | 窗口名带组织和「已用/额度 cr」，一眼看出是哪一份、用了多少 |

**进度条用 `已用 + 预扣`**，只算已用会严重低估：实测某个时刻已用 41%，
加上预扣后是真实消耗的 96%。预扣不是押金，是预扣——停掉工作区时它不会返还，
只是从「预扣」划到「已用」。

额度查不到时写明原因（例如「缺 group-resource:r」），不画进度条，不拿 0 冒充。
地址默认打码，因为面板常被截图分享；要看完整地址设 `CNB2API_SHOW_FULL_HOST=1`。

## 7. 工具

插件注册四个工具，agent 可以自己调用：

| 工具 | 作用 |
|---|---|
| `cnb2api_workspace_status` | 查状态、仓库、地址、空闲多久、是否被额度拦住 |
| `cnb2api_workspace_start` | 拉起（会现查一次额度） |
| `cnb2api_workspace_stop` | 停止，止住核时 |
| `cnb2api_quota` | 查该组织的 AI credits / 核时 |

多账号时工具会并行跑每个账号，结果按账号分块，小块之间不会串。

## 8. 选项

全部可选；改完选项需要重启 magpie 才生效。

| 选项 | 默认 | 说明 |
|---|---|---|
| `token` | — | CNB 访问令牌，建议用登录表单填 |
| `proxyKey` | — | `.cnb.yml` 里的 PROXY_KEY |
| `repo` | 自动 | 留空自动识别；填 `org/repo` 可固定 |
| `org` | — | 组织，多个用逗号分隔 |
| `models` | `deepseek-v4.1-flash` | 模型清单，逗号分隔 |
| `branch` | `main` | 拉起工作区用的分支 |
| `checkSeconds` | `120` | 巡检间隔（最少 30 秒） |
| `autoStart` | `true` | 工作区停了是否自动拉起 |
| `idleStopMinutes` | `0` | 空闲多少分钟自动停止；`0` = 不开 |
| `port` | `9001` | 工作区里 cnb2api 的端口 |
| `creditFloorPercent` | `1` | 可用额度低于这个百分比就不启动；`0` = 关闭 |

`repo` 接受多种写法：

```
https://cnb.cool/alice/my-gateway
https://cnb.cool/alice/my-gateway/-/tree/main
git@cnb.cool:alice/my-gateway.git
alice/my-gateway
my-gateway                    ← 只写名字，组织自动补
```

## 9. 安全

| 层 | 隔离方式 |
|---|---|
| 插件代码 | 无硬编码凭据 |
| 配置 | 登录信息存在 magpie 自己的 `plugin-auth.json`（权限 600） |
| 账号状态 | 按 `用户名 \| 组织/仓库` 分上下文，异步调用链隔离 |
| 缓存键 | 令牌只存指纹，不存明文 |
| 上游鉴权 | 发给 cnb2api 的永远是 PROXY_KEY，不是 CNB 访问令牌 |

### 多账号为什么不会串

插件函数只被调用一次，所有账号共用同一份闭包。若用普通变量记「当前账号」，
两个账号并发请求时就会互相干扰。插件用 `AsyncLocalStorage` 把账号上下文绑在
异步调用链上；跨 await 之后一律重新进入作用域，不依赖上下文残留。

## 10. 常见现象

| 现象 | 原因 | 处理 |
|---|---|---|
| `401`（CNB） | 令牌无效或过期 | CNB → 头像 → 访问令牌，重新生成 |
| `402 [EXCEEDING_LIMIT]` | 组织额度用尽 | 补足额度；期间不会自动启动 |
| 地址是 placeholder | 还没取到地址 | 等 30–90 秒（冷启动），或检查日志权限 |
| 面板没有额度数字 | 缺 `group-resource:r` | 编辑令牌补勾 |
| `stop` 提示没权限 | 缺 `account-engage:rw` | 编辑令牌补勾 |
| 账号显示成 key 尾缀 | 登录信息没带用户名 | 重新执行一次 `magpie plugin login cnb2api` |

日志带账号前缀，方便分清是谁：

```
[cnb2api] [alice | acme/my-gateway] 已就绪：860l****-9001.cnb.run
[cnb2api] [alice | @beta] 放弃等待：仓库 beta/gateway 不存在
```

---

## 11. 已知限制

- 两个账号指向同一仓库时会共用同一个工作区，地址和额度都是同一份。
- 工作区冷启动要 30–90 秒，首次请求会等。
- `cnb.run` 是泛解析，无法靠 DNS 或 HTTP 探测猜地址，必须读日志。
- PROXY_KEY 按仓库保存：换仓库就要换密钥。

## 开发

```bash
npm test
```

代码分两层：

| 文件 | 职责 |
|---|---|
| `toolkit.mjs` | 纯函数：地址、仓库写法、身份、额度、选项。无 IO、无定时器 |
| `index.mjs` | 编排：CNB OpenAPI、巡检、启动、额度闸门、magpie 钩子与工具 |
| `test/*.test.mjs` | 纯函数测试与带本地 mock 的行为测试 |

测试用 bun 或 Node 20+ 都能跑，不连真实 CNB，不启动真实工作区。
