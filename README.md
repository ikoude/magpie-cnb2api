# magpie-cnb2api

把 CNB 工作区中运行的 cnb2api 接入 magpie，作为一个供应商（provider）。安装后，
magpie 中新增名为 **CNB2API** 的供应商，所有 agent 均可直接选用，行为与内置供应商一致。

插件处理两类问题：**工作区地址漂移**、**工作区被平台停止**。同时提供两项信息：
工作区所属组织的**真实额度**，以及按「用户 + 组织/仓库」划分的**多账号**支持。

> 本文中的组织名、用户名、仓库名、额度与地址均为示例（`alice`、`acme`、
> `acme/gateway`），不代表任何真实数据。

## 1. 概述

### 1.1 解决的问题

cnb2api 运行在 CNB 工作区内，存在两个固有约束：

| 问题 | 表现 | 插件行为 |
|---|---|---|
| **地址漂移** | 工作区每次重启，`<随机串>-<端口>.cnb.run` 随之变化 | 后台巡检，地址变化后自动跟随 |
| **工作区停止** | 平台回收工作区，停止后不再响应请求 | 定时检查，停止后调用 OpenAPI 启动 |

### 1.2 提供的能力

- **地址跟随**：地址变化后立即更新，请求失败时重新识别并重试一次。
- **自动启动**：工作区停止后自动启动；启动前检查所属组织额度，额度用尽时不启动。
- **额度显示**：在 magpie 的用量面板显示工作区的 AI credits 与核时（core-hours）。
- **多账号**：同一 magpie 可登录多个 CNB 账号，每个「用户 + 组织/仓库」为独立账号。

### 1.3 边界

- **不停止工作区**：插件不提供空闲自动停止，也不提供停止工具。工作区重启需
  30–90 秒且地址会变化，停止正在使用的工作区代价高于节省的核时。
- **不代替用户选择仓库**：仓库决定地址、账号与巡检对象，错误选择不会产生可见报错，
  因此必须由用户确认。
- **不合并组织额度**：额度按组织计算，一个账号只使用其所属组织的额度，
  CNB 不支持跨组织合并。

## 2. 快速开始

```bash
# 1. 安装
magpie plugin add npm:magpie-cnb2api

# 2. 登录（按提示填写令牌、选择组织与仓库、填写 PROXY_KEY）
magpie plugin login cnb2api

# 3. 为 agent 指定模型
magpie claude cnb2api/deepseek-v4.1-flash

# 4. 查看状态与额度
magpie quota
```

安装完成后，magpie 的 **Plugins** 列表中出现 **CNB2API**。首次登录需要准备两项凭据，
区别见 [5.1 两类凭据](#51-两类凭据)。

## 3. 概念

以下四种信息的粒度不同，是理解后续全部行为的前提。

### 3.1 四种信息的粒度

| 信息 | 粒度 | 说明 |
|---|---|---|
| 账号 | 用户 + 组织/仓库 | 同一组织下两个仓库为两个账号 |
| 额度 | 用户 + 组织 | AI credits 与核时按组织计算，不细分到仓库 |
| 工作区地址 | 用户 + 组织/仓库 | 每个仓库有独立工作区，地址各自独立 |
| PROXY_KEY | 组织/仓库 | 配置在该仓库 `.cnb.yml` 的 `env` 中，不同仓库可以不同 |

结论：账号身份为 **(用户, 组织/仓库)**。不同组织额度不同；同一组织的不同仓库额度相同、
地址不同。

### 3.2 账号命名

账号在界面、日志与工具输出中统一表示为 **`用户 | 组织/仓库`**：

```
alice | acme/gateway
```

分隔符使用竖线而非 `@`：`组织/仓库` 本身包含 `/`，追加 `@` 后形如邮箱地址，
无法区分用户与组织。

### 3.3 多账号的四种情形

| 情形 | 示例 | 额度 | 地址 |
|---|---|---|---|
| 独立账号 | `alice \| acme/gateway`、`bob \| beta/proxy` | 各自组织 | 各自独立 |
| 团队账号 | `alice \| acme/gateway`、`bob \| acme/gateway` | 共用 acme | 各自独立 |
| 一名用户多个组织 | `alice \| acme/gateway`、`alice \| gamma/gateway` | 按组织分别计算 | 各自独立 |
| 同组织多个仓库 | `alice \| acme/gateway-a`、`alice \| acme/gateway-b` | 共用 acme | 各自独立 |

切换使用哪个账号在 magpie 中完成。一个账号不能同时使用两个组织的额度。

### 3.4 PROXY_KEY 与账号身份

**PROXY_KEY 不参与身份判定。** 它是 api 类型的 apiKey，同一份 `.cnb.yml` 常被多人
共用，key 可能完全相同。若以它作为身份，无论选择哪个组织与仓库，所有登录都会被识别为
同一账号。

插件仅以 CNB 令牌读取的用户，加上所选组织/仓库作为身份；PROXY_KEY 按仓库保存在该账号
的 metadata 中，只用于向 cnb2api 发起请求。

## 4. 安装与登录

### 4.1 安装

```bash
magpie plugin add npm:magpie-cnb2api      # 从 npm 安装
magpie plugin add ./magpie-cnb2api        # 从本地目录安装：不复制文件，修改代码直接生效
```

进入 magpie 社区清单后，也可使用 `magpie plugin add cnb2api`。

### 4.2 登录流程

```bash
magpie plugin login cnb2api
```

组织和仓库均为下拉选择，选项来自令牌实际可访问的列表：

```
① CNB 访问令牌 · 在 CNB 头像 → 访问令牌 页面生成          手填
② 选择组织 · 该令牌可访问 N 个组织，每个组织对应一个账号    下拉
     acme │ beta │ gamma
③ 选择仓库 · acme 下有 2 个运行 cnb2api 的仓库             下拉
     acme/gateway（运行中）│ acme/worker（已停止）│ 手动填写仓库名…
④ PROXY_KEY · 取自该仓库 .cnb.yml 的 env                   手填
⑤ 添加其他组织 · 选择「完成登录」即保存                    下拉
     完成登录 · 仅添加这 1 个 │ 添加组织：beta │ 添加组织：gamma
```

顺序为 **令牌 → 组织 → 仓库 → 该仓库的密钥 → 是否继续添加**。PROXY_KEY 属于仓库，
因此确定仓库后立即询问；最后一步仅决定是否继续，完成后登录结束。

### 4.3 连续添加多个组织

选择继续添加后，第二个仓库起无需重复粘贴密钥：

```
beta/gateway 的 PROXY_KEY · 每个仓库各配置一份
  与上一个仓库相同  — 沿用 acme/gateway 的值
  填写其他值        — 该仓库 .cnb.yml 中是另一个值
```

选择「与上一个仓库相同」时沿用上一个仓库的值（同一份 `.cnb.yml` 复制到多个仓库较为常见），
选择「填写其他值」时弹出输入框。插件不会将一个仓库的密钥应用到另一个仓库。

仅添加一个组织同样有效：完成步骤 ④ 后选择「完成登录 · 仅添加这 1 个」。其余组织可在需要时
再次执行 `magpie plugin login cnb2api`，代价是重新填写令牌与 PROXY_KEY，账号本身无差异。
连续添加多组织仅用于减少令牌粘贴次数。

### 4.4 单个账号的命令行配置

```bash
magpie plugin options magpie-cnb2api '{
  "token": "你的 CNB 访问令牌",
  "proxyKey": "sk-你的PROXY_KEY",
  "repo": "acme/gateway"
}'
```

也可在 magpie 界面 → Plugins → CNB2API → Options 中填写。该方式仅配置**一个**账号
（组织与仓库由 `repo` 决定），多账号请使用登录表单。

### 4.5 仓库选择规则

地址按仓库计算，未指定仓库则无法确定跟随哪个工作区。候选列表经筛选生成，筛选条件是
该组织下存在工作区、且启动日志中出现过 `PROXY_URI=`；名称包含 `cnb2api` 的仓库直接收录。
筛选仅用于缩小范围，不代替用户决定：

- 存在候选：全部列出，**即使只有一个也需用户确认**（选项标注「运行中 / 已停止」）。
- 候选为空：列表末项固定为 **「手动填写仓库名…」**，选择后手动输入。
  日志已轮转、仓库刚创建、工作区属于他人，均可能导致漏筛。
- 无任何候选：直接要求手动填写，未填写则失败。

未选择仓库时登录直接失败，插件不做推断。自动选择错误仓库的后果不可见：地址、账号与巡检
将全部指向另一仓库。因此候选判断**不依赖仓库名称**，仅依据日志中的 `PROXY_URI=`：

```
alice/blog           日志: "listening on 3000"        → 不收录
acme/my-ai-gateway   日志: "PROXY_URI=https://…"      → 收录
```

### 4.6 账号身份的写入与覆盖

所选组织与仓库会写入账号身份，因此**同一份令牌添加几个组织即为几个账号**。
如需更换某账号的组织或仓库，重新登录即可：相同的「用户 + 组织/仓库」会替换原条目，
不会重复新增。

## 5. 凭据与权限

### 5.1 两类凭据

| 凭据 | 格式 | 用途 | 获取位置 |
|---|---|---|---|
| **CNB 访问令牌** | 字母数字字符串，**不以 `sk-` 开头** | 调用 CNB OpenAPI：列出工作区、读取日志、启动工作区 | CNB → 头像 → 访问令牌 |
| **PROXY_KEY** | 通常以 `sk-` 开头 | 调用**该仓库**工作区内的 cnb2api 网关 | 该仓库 `.cnb.yml` 中 `env` 的 `PROXY_KEY` |

两者填写颠倒时，插件给出明确提示：

```
该值以 sk- 开头，是 PROXY_KEY，不是 CNB 访问令牌 · 请重新填写令牌
```

### 5.2 PROXY_KEY 的粒度

PROXY_KEY 的粒度是**仓库**，不是账号，也不是网关：

| 情况 | 是否相同 |
|---|---|
| 同一仓库、不同用户的令牌 | 相同（同一份 `.cnb.yml`） |
| 同一用户的两个仓库 | **可以不同** |
| 同一组织下的两个仓库 | **可以不同** |

插件无法自动获取该值，原因有两点：

- 它仅是该仓库 `.cnb.yml` 中 `env` 的一个值。CNB OpenAPI 无法读取工作区环境变量；
  若可读取，任何持有令牌的人都能读取他人的密钥。
- 自动读取需为令牌增加 `repo-code:r`（读取仓库文件）以解析 `.cnb.yml`，而该文件可能
  使用 `${SECRET}` 一类引用，解析结果并非真实值。为减少一次粘贴而开启读取代码的权限，
  代价不合理。

因此多仓库登录时按仓库分别询问、分别保存。缺少某个仓库的密钥时，登录返回具体仓库名
（`以下仓库缺少 PROXY_KEY：acme/worker`），不会保存密钥为空的账号。

### 5.3 令牌权限

权限决定可用功能，按需勾选。

#### 必需（未勾选则不可用）

| Scope | 用途 | 缺少的后果 |
|---|---|---|
| `repo-cnb-trigger:r` | 读取启动日志，提取工作区地址 | **插件不可用**：无法获取地址 |
| `account-engage:r` | 列出令牌属主的工作区 | **插件不可用**：无法获取工作区 |

#### 建议勾选

| Scope | 用途 | 缺少的后果 |
|---|---|---|
| `repo-cnb-trigger:rw` | 调用 API 启动已停止的工作区 | 地址仍可跟随，但工作区停止后不会自动启动，需在网页手动启动 |

`rw` 包含 `r` 的能力，因此**最小可用组合为 `repo-cnb-trigger:rw` 与 `account-engage:r`**。

#### 按功能选配

| Scope | 开启的功能 | 缺少的后果 |
|---|---|---|
| `group-resource:r` | 用量面板显示 AI credits 与核时 | 面板不显示额度数字 |
| `repo-cnb-detail:r` | 获取地址前先查询工作区详情（更快） | 回退到读取日志，速度略慢，无功能损失 |
| `repo-cnb-history:r` | 按模型统计 token 与 credit | 无影响，仅缺少明细 |

#### 不需要

| Scope | 原因 |
|---|---|
| `repo-code:r` | 插件不读取仓库代码 |

#### 快速对照

| 需求 | 需勾选 |
|---|---|
| 最小可用 | `repo-cnb-trigger:rw`、`account-engage:r` |
| 需要额度显示 | 上述两项 + `group-resource:r` |
| 全部功能 | 上述三项 + `repo-cnb-detail:r`、`repo-cnb-history:r` |

权限不足时插件不会静默失败：日志与 `magpie quota` 会说明缺少哪一项、影响范围与补救方式。

## 6. 用量与额度

### 6.1 面板结构

面板的账号卡把窗口排成一条**额度行**：只排前两个窗口，其余只进悬停提示。
所以额度排在前面，工作区状态排在它们之后：

```
alice | acme/gateway      closed  ⟳                          首选
   AI credits      ▬▬▬▬▬  800 / 1200 cr · 已用 67%
   dev core-hours  ▬      4.4 / 1600 h · 已用 0.3%

alice | beta/gateway      running ⟳                        设为首选
   AI credits      ▬▬▬▬▬  1200 / 1200 cr · 已用 100%
   dev core-hours  ▬      48 / 1600 h · 已用 3%
```

| 顺序 | 窗口 | 回答的问题 |
|---|---|---|
| 1 | `AI credits` | credits 还剩多少（余额为 0 时行首标 `已用尽`） |
| 2 | `dev core-hours` | 核时还剩多少 |
| 3 | `workspace` | 工作区在不在、地址通不通（面板里在悬停提示中；一句话版见账号名后的徽标） |
| 4 | `AI credits 明细` / `dev core-hours 明细` | 纯文字明细，只给读不到进度条的卡片用 |

前两位是额度、不是 `workspace`，因为额度行只有一行：`workspace` 若排第一，
credits 就会被挤到同一行右侧，工作区状态和额度混读成一句。
`magpie quota`（终端）按同一顺序列出全部窗口，`workspace` 紧跟额度之后。

额度相关的话术只出现在额度行，`workspace` 行不夹带，避免同一句话读两遍。

### 6.2 工作区状态行

该行回答「工作区在不在、地址通不通」，格式统一为 `<状态词> · <地址或原因>`，
段间用 ` · `、句内补充用 `，`。面板的额度行只放额度，这条行出现在额度之后的
悬停提示里；账号名后的徽标给出第一眼答案——**能不能用**（`可用` / `无额` / `掉线` /
`停止` / `未建` / `启动` / `异常` / `未知`）。状态词只有七个：

| 状态词 | 含义 | 后面跟 |
|---|---|---|
| `就绪` | 工作区在跑、地址通、额度够 | 打码后的地址 |
| `运行中` | 工作区在跑，但 AI credits 已归零 | 打码后的地址 |
| `无响应` | 工作区在跑，但地址连不上 | 地址 |
| `已停止` | 有工作区实例，当前没运行 | 自动启动进度（如相关） |
| `无工作区` | 该仓库从未启动过工作区 | 自动创建进度（如相关） |
| `启动中` | 刚提交启动，还没就绪 | — |
| `不可用` | 令牌、权限、仓库这类硬失败 | 具体原因 |

徽标只占两个字，回答的是**可用性**而不是「在不在跑」——在跑不等于能用：
额度归零、地址不通时机器在转，请求却全被拒（402 / 连不上）。所以「运行」这个词
在徽标里不存在，拆成了 `可用` / `无额` / `掉线` 三种结论。
字数一样、中文字宽相同，再加上面板给那一格留的 `min-width: 3em`，
不同账号的徽标就落在同一列上，不会随组织名长短漂移。

| 徽标 | 能不能用 | 什么时候出现 | 对应状态词 |
|---|---|---|---|
| `可用` | 能 | 在跑、地址通、额度够 | 就绪 |
| `无额` | 不能（机器在跑） | 组织 AI credits 归零，请求会被 402 | 运行中 |
| `掉线` | 不能（机器在跑） | 在跑，但地址探不通 | 无响应 |
| `停止` | 不能 | 有实例，当前没运行 | 已停止 |
| `未建` | 不能 | 该仓库没有任何工作区记录 | 无工作区 |
| `启动` | 不能（过渡） | 刚提交启动，还没就绪 | 启动中 |
| `异常` | 不能 | 令牌、权限、仓库这类硬失败 | 不可用 |
| `未知` | 还不知道 | 首屏还没查到 | 识别中 |

`未建` 只在这个仓库**一条工作区记录都没有**时出现，判断依据是
`/workspace/list` 的**全量**结果（不带 `slug` 参数）。服务端那个 `slug` 过滤会漏记录：
2026-11-20 实测 `ikelaode/cnb2api` 在平台上共 5 条（1 running + 4 closed），
`?slug=ikelaode/cnb2api` 只回 1 条 —— 那 4 条的 `repo_url` 指向别的组织，被服务端当成
"不属于这个 slug"滤掉了。该组织一旦没有 running 实例，列表就是空的，插件就会误判
"从未建过"、面板显示 `未建`。所以现在拉全量、自己按仓库筛（`slug` 优先，缺了退回 `repo_url`）。

```
就绪 · 1a2b****-9001.cnb.run
```

前 4 位用于识别，端口与域名用于判断是否正常。端点默认打码，因为用量面板常被截图分享；
打码只影响显示，实际请求始终用完整地址。需要看完整地址时：

```bash
CNB2API_SHOW_FULL_HOST=1 magpie
```

**工作区在跑不等于能用。** 组织 AI credits 归零后，平台不会停掉已运行的工作区，
但所有模型请求会被上游以 `402 EXCEEDING_LIMIT` 拒绝。所以额度归零时状态词从
`就绪` 降为 `运行中`——只降级、不解释，解释放在下面那行：

```
workspace     运行中 · 1a2b****-9001.cnb.run
AI credits 100% (已用尽 · 1200 / 1200 cr · 赠送 +600 · 冻结 0 · 可用 0)
```

首屏尚未查到状态时只显示 `识别中`，不叠加任何额度结论，免得一句话里自相矛盾。

### 6.3 额度含义与显示规则

| 显示项 | 含义 |
|---|---|
| `800 / 1200 cr` | 已用 / 总额（单位为 credit，1 credit ≈ 0.001 元） |
| `冻结 100` | 已预扣、尚在计费周期内未结算的部分 |
| `可用 1100` | 当前可用额度 = 总额 − 已用 − 冻结 |
| `赠送 +600` | 额外赠送额度，已计入总额（名目由 CNB 提供） |
| `+1024 已过期` | 赠送额度已失效，但仍占用总额 |

显示规则：

- 所有账号使用统一结构：`进度条（百分比）+ (已用 x / y 单位 · 赠送 · 冻结 · 可用)`。
- 文字里自带 `已用 x / y`：进度条只有百分比，不写数字就看不出还剩多少。余额为 0 时
  改为 `已用尽 · x / y`，`已用尽` 居首，与 `就绪`/`运行中` 一样先给结论。
- 冻结为 0 时仍显示 `冻结 0`，不省略——省略会让人分不清「没有冻结」和「不知道」。
- 整数不保留 `.0`（显示 `0` 而非 `0.0`）。

### 6.4 查不到额度

额度接口未返回数据时，面板不空白，而是在该行说明原因：

```
AI credits   查不到 · quota HTTP 403
```

| 显示 | 原因 | 处理 |
|---|---|---|
| `查不到 · quota … HTTP 403` | 令牌缺少 `group-resource:r` | 勾选该权限后重启工作区 |
| `查不到 · 仓库未确定` | 账号尚未绑定仓库（旧登录条目） | 重新登录 |
| `查不到 · … timeout` | CNB 接口本次未返回 | 下次刷新自动重试，无需处理 |
| `可用 500 / 1166 cr · 已用量未取到` | 总额已获取、已用量未获取 | 下次刷新补齐 |

额度面板不会因工作区冷启动而空白。面板是同步钩子，宿主无法等待 30–90 秒的冷启动：
状态未就绪时先显示 `不可用 · 工作区已停止`，额度照常返回，启动工作在后台继续。

### 6.5 额度用尽时的行为

工作区停止且需要启动时，插件先查询所属组织额度；AI credits 用尽则不启动：

```
AI credits 已用尽 · 已用 1200 / 1200 cr · 恢复后自动启动
```

cnb2api 为 AI 网关，credits 用尽后对每个请求返回：

```
402 [EXCEEDING_LIMIT] AI 积分已用尽，请联系根组织管理员提升配额
```

此时启动工作区只会消耗 30–90 秒冷启动时间与核时，最终仍返回 402。因此：

- **不提交** `/workspace/start`，日志仅记录一次原因，同一结论不重复输出。
- 请求立即失败并说明原因，不再等待一个不会出现的地址。
- 巡检按 `checkSeconds` 间隔检查额度，**额度恢复后自动启动**，无需人工干预。

边界情况：

| 情况 | 行为 |
|---|---|
| 额度查不到（缺少 `group-resource:r`、接口异常） | **照常启动**：阻止一个可用工作区的代价高于放过一个将返回 402 的工作区 |
| 余额很少但大于 0 | 照常启动，不做提前拦截 |
| 工作区已在运行 | 与启动无关；请求被 402 拒绝时，错误信息补充「额度用尽期间不会自动启动」 |

额度按**组织**计算，与用量面板口径一致；同一组织下的多个仓库共用同一份额度。

## 7. 工具与选项

### 7.1 工具

插件注册三个工具，供 agent 调用：

| 工具 | 作用 |
|---|---|
| `cnb2api_workspace_status` | 查看运行状态、所属仓库、当前地址、工作区编号 |
| `cnb2api_workspace_start` | 启动工作区；工作区已停止时使用，额度用尽时拒绝并说明原因 |
| `cnb2api_quota` | 查询所属组织的核时与 AI credits 余量 |

### 7.2 工作区生命周期

插件**不执行空闲自动停止**，也不提供停止工具。工作区停止后重启需 30–90 秒且地址会变化，
为节省核时停止正在使用的工作区，会使下一次请求额外等待一分钟以上。需要停止时，
请在 CNB 网页操作。

如需查看可用核时，使用 `cnb2api_quota` 或 magpie 用量面板。

### 7.3 选项

全部选项均可选，未填写时使用默认值或登录信息。

> 选项在插件加载时读取，修改后需重启 magpie 生效。

| 选项 | 默认值 | 说明 |
|---|---|---|
| `token` | — | CNB 访问令牌，建议通过登录表单填写 |
| `proxyKey` | — | 该仓库 `.cnb.yml` 中的 PROXY_KEY |
| `repo` | — | 建议通过登录表单选择；地址按仓库计算，必须指定 |
| `models` | `deepseek-v4.1-flash` | 逗号分隔的模型列表 |
| `branch` | `main` | 启动工作区时使用的分支 |
| `checkSeconds` | `120` | 巡检间隔（秒） |
| `autoStart` | `true` | 工作区停止后是否自动启动；额度用尽时不启动 |
| `port` | `9001` | cnb2api 监听端口 |

`repo` 支持以下写法：

```
https://cnb.cool/<组织>/<仓库>
https://cnb.cool/<组织>/<仓库>/-/tree/main
git@cnb.cool:<组织>/<仓库>.git
<组织>/<仓库>
<仓库>                    仅填写名称，组织取登录时所选
```

### 7.4 刷新时机

| 时机 | 行为 |
|---|---|
| 登录后 | 立即执行一轮识别 |
| 定时 | 每 `checkSeconds` 秒（默认 120） |
| 请求失败 | 重新识别地址并重试一次 |
| 凭据变更 | 重置该账号状态并重新识别 |

凭据变更时会清除此前的错误状态，更换令牌后无需重启 magpie。

## 8. 排障、限制与卸载

### 8.1 常用命令

```bash
magpie logs                          # 查看插件日志（带账号前缀）
magpie quota                         # 查看当前额度
magpie quota refresh cnb2api --json  # 重新获取一次，查看原始数据
```

日志中的账号前缀用于区分账号：

```
[alice | acme/gateway]  就绪 · 1a2b****-9001.cnb.run
[alice | gamma/gateway] 就绪 · 3c4d****-9001.cnb.run
```

### 8.2 常见现象

| 现象 | 原因 | 处理 |
|---|---|---|
| `401`（CNB OpenAPI） | 令牌无效或已过期 | 在 CNB → 头像 → 访问令牌 重新生成 |
| `401`（请求 cnb2api） | 该账号的 PROXY_KEY 与仓库 `.cnb.yml` 不一致 | 重新登录该账号，按该仓库的值填写 |
| `402 [EXCEEDING_LIMIT]` | 所属组织 AI credits 用尽 | 联系根组织管理员提升配额；期间插件不会自动启动工作区 |
| 提示「缺少必需权限」 | 令牌未勾选对应 scope | 编辑令牌勾选后重启工作区 |
| 仓库不存在 | `repo` 填写错误，或令牌无权访问 | 核对组织与仓库 |
| 地址为 placeholder | 尚未获取到地址 | 等待 30–90 秒（工作区冷启动） |
| 额度面板无数字 | 缺少 `group-resource:r` | 勾选后重试 |

### 8.3 已知限制

- 两个账号指向**同一仓库**时共用同一工作区，地址与额度为同一份。这是 CNB 侧模型决定的，
  插件无法绕过。
- PROXY_KEY 按仓库保存：更换仓库即更换密钥，需重新登录（插件不会沿用旧仓库的密钥）。
- 凭据保存在 magpie 配置文件中。多人共用同一台机器时，需注意文件权限。
- 工作区冷启动需 30–90 秒，首次请求会等待，之后使用缓存。
- 账号名 `用户 | 组织/仓库` 同时是 magpie 的持久化键。改名或删除账号后，旧的额度、
  历史与模型勾选不会自动消失，可使用 `npx magpie-cnb2api-prune` 清理（见 8.4）。
- 从旧版本升级时，账号名格式变过一次，需要手动处理旧账号（见 8.5）。

### 8.4 卸载与缓存清理

```bash
magpie plugin rm magpie-cnb2api        # 移除插件
magpie plugin logout cnb2api           # 注销该 provider 的登录
```

卸载不会自动清除已写入的账号与额度缓存。

magpie 以**账号名**为键，将账号相关数据保存在 `~/.config/magpie`：

| 文件 | 内容 |
|---|---|
| `plugin-auth.json` | 账号本身（令牌、PROXY_KEY、组织/仓库） |
| `quotas.json` | 每个账号最后一次额度快照 |
| `quota-history.json` | 每个账号的额度历史 |
| `providers.json` | 每个账号的名称与模型勾选；卸载插件时整块移入 `pluginLeft`，重装时恢复 |
| `served.json`、`affinity.json` | 使用过该账号的会话 |

删除账号时，magpie 仅删除 `plugin-auth.json` 中的条目，上述按账号名保存的数据不会回收；
卸载插件同理，重装后 `pluginLeft` 中的旧账号名会恢复。因此重装后出现的旧账号来自宿主缓存，
插件本身仅在内存中缓存，进程退出即失效。

清理方式（先退出 magpie，默认仅预览）：

```bash
npx magpie-cnb2api-prune            # 列出将删除的条目
npx magpie-cnb2api-prune --apply    # 执行，自动备份
```

从本地目录安装时，也可执行 `node tools/magpie-prune.mjs`。

> 账号名格式确定后不应再修改：`用户 | 组织/仓库` 是 magpie 的持久化键，
> 修改格式等同于新增账号，旧键将成为孤立数据。

### 8.5 从旧版本升级

早期版本的账号名用过 `用户@cnb.cool` 和 `用户+组织@cnb.cool`，当前格式是
`用户 | 组织/仓库@cnb.cool`。magpie 以账号名为键保存数据，格式一变，旧账号在
`plugin-auth.json` 里仍然是一条**有效账号**，不会被覆盖或删除。

所以升级后重新登录，同一个组织会留下两个账号：各自统计额度、各自出现在面板上，
请求也可能被分派到两者之一。重装插件不能消除——卸载只处理 `providers.json` 里的配置，
账号表不随插件删除。

处理步骤：

1. 在账号列表里找出旧格式那个（名字含 `+`，或只有用户名、没有组织）。
2. 删除它，再重新登录一次该组织，新账号使用当前格式。
3. 退出 magpie，执行 `npx magpie-cnb2api-prune` 清理旧账号名留下的额度历史。

`magpie-cnb2api-prune` 会主动检测这种情况，输出形如：

```
⚠ 同一组织存在多个账号标识：1 组
  组织 acme
    · alice | acme/gateway@cnb.cool   [当前格式]   cnb2api#a1oeduxl178o46l
    · alice+acme@cnb.cool             [旧格式（加号拼组织）]   cnb2api#oldfmt
```

这些条目不会被 `--apply` 删除：它们是活账号，删掉就得重新登录，交由你判断。

## 9. 开发

源码为单个 `index.mjs`，按「纯函数 → 账号作用域 → CNB OpenAPI → 状态机 → 登录流程 → 宿主协议」分段，文件头有索引。无运行时依赖，要求 Node ≥ 20。

```bash
npm test     # 6 个测试文件，各自独立进程
```

| 文件 | 覆盖内容 |
|---|---|
| `test/pure.test.mjs` | 额度配平、特权解析、地址打码、日志取地址、仓库名归一 |
| `test/login-multi-org.test.mjs` | 一次登录写多个账号：账号 id 稳定、key 按仓库、宿主不支持时的降级 |
| `test/smoke.test.mjs` | 登录问答顺序、usage 面板结构、两个工具的输出 |
| `test/quota-gate.test.mjs` | 额度用尽不启动、结论缓存、402 翻译、额度恢复后补启动 |
| `test/usage.test.mjs` | 面板不被启动与探活拖住、查不到额度时写明原因、额度行由两个额度打头 |
| `test/ready-retry.test.mjs` | 工作区停止后等到新地址再重试 |

测试以假的 `fetch` 替代网络，不访问 CNB，也不读写 `~/.config/magpie`；`test/` 不包含在 npm 包内。
